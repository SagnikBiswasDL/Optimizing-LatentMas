\begin{frame}{Three checks}

Same model, same GPU. Pool: \textbf{29.5 GiB} (12{,}102 blocks).
One 32k decode is \textbf{5.0 GiB}. One block is 2.5 MiB.

\begin{itemize}
  \item Clear the cache and the same prompt is computed again. Send it once more and the saved result is used.
  \item A shorter prompt uses less GPU memory while those 32k tokens are generated.
  \item Five long prompts do not fit. vLLM throws a running request out and starts it over. Five short prompts fit, so that does not happen.
\end{itemize}

\end{frame}

\begin{frame}{6.2 GiB vs 5.2 GiB per job, caching off}

Long prompt: 6.2 GiB per request. Five are 31.2 GiB, over the 29.5 GiB pool.
Short prompt: 5.2 GiB. Five are 25.8 GiB, inside it.

\begin{center}

\bottomrule

\end{center}

The 4-request gap is 4.3 GiB. The shorter prefix predicts 4.3 GiB.
